# وصل کردن چارتون به Supabase

اپ بدون سرور هم کامل کار می‌کنه و پیشرفت رو روی دستگاه نگه می‌داره. با Supabase این‌ها روشن می‌شن:

- ثبت‌نام و ورود با ایمیل (پیش‌فرض) یا شماره موبایل ایران و رمز عبور (فعلاً بدون کد تأیید)، روی همه‌ی دستگاه‌ها
- ذخیره‌ی ابری پیشرفت و ادغام خودکار بین دستگاه‌ها (هیچ درسی از دست نمی‌ره؛ عددها بیشترین مقدار رو نگه می‌دارن)
- لیگ هفتگی با بازیکن‌های واقعی (صندلی‌های خالی با رقبای شبیه‌سازی‌شده پر می‌شن)
- گفتگو: گروه‌هایی مثل گروه‌های تلگرام، با پیام متنی و تحلیل همراه نمودار از شبیه‌ساز
- دستیار هوش مصنوعی «شمعک» که اول فهرست گفتگوها پین شده و دوره‌ها، جای کاربر توی مسیر، اشتباه‌ها، پوزیشن‌ها، سفارش‌ها و معامله‌های شبیه‌سازش رو می‌بینه

## پروژه‌ی مشترک: چارتون جدا از بقیه‌ی اپ‌ها

پروژه‌ی Supabase چارتون با اپ‌های دیگه مشترکه، پس چارتون عمداً یه گوشه‌ی جدا داره:

- همه‌ی چیزهایی که می‌سازه اسمش با `tradingo_` شروع می‌شه: جدول‌های حساب و پیشرفت (`tradingo_accounts`، `tradingo_sessions`، `tradingo_progress`، `tradingo_weekly_xp`)، جدول‌های گفتگو (`tradingo_rooms`، `tradingo_room_members`، `tradingo_messages`، `tradingo_message_reports`) و چند تابع.
- از **Supabase Auth استفاده نمی‌کنه**؛ حساب‌ها (ایمیل یا موبایل + رمزِ هش‌شده با bcrypt) توی `tradingo_accounts` هستن. پس کاربرهای چارتون توی `auth.users` و جدول‌هایی مثل `profiles` یا `users` اپ‌های دیگه نمی‌رن و تنظیمات ورود پروژه (مثل Confirm email) لازم نیست تغییر کنه.
- به هیچ جدول، تابع یا تنظیمی از اپ‌های دیگه دست نمی‌زنه. قبل از نوشتن، اسم‌های موجود پروژه بررسی شد و هیچ‌کدوم با `tradingo_` شروع نمی‌شه.
- جدول‌ها RLS دارن و هیچ policy ندارن؛ یعنی از بیرون مستقیم خونده یا نوشته نمی‌شن و اپ فقط از طریق توابع `tradingo_*` باهاشون کار می‌کنه.
- حذف کامل: [`supabase/tradingo_uninstall.sql`](../supabase/tradingo_uninstall.sql) فقط همین‌ها رو پاک می‌کنه.

## وضعیت فعلی

**نصب شده (۲۳ سپتامبر ۲۰۲۶).** بعد از نصب، اثر انگشت ساختار کل پروژه (جدول‌ها، ستون‌ها، policyها، توابع، تریگرها و دسترسی‌ها، به‌جز `tradingo_*`)
قبل و بعد مقایسه شد و دقیقاً یکی بود؛ تعداد کاربرهای `auth.users` و policyها هم تغییری نکرد. ثبت‌نام، ورود، ذخیره، بازیابی، لیگ و خروج
از طریق API عمومی و با کد خود اپ روی سرور تست شد و حساب‌های آزمایشی بعدش پاک شدن.

**گفتگو نصب شده (۲۳ سپتامبر ۲۰۲۶، [`20260925000000_tradingo_chat.sql`](../supabase/migrations/20260925000000_tradingo_chat.sql)).** این بار هم اثر انگشت
ساختار بقیه‌ی پروژه قبل و بعد یکی بود. عضویت، پیام، مسدود شدن لینک، خوندن بدون حساب و بسته بودن دسترسی مستقیم به جدول‌ها روی سرور تست شد و
حساب‌ها و پیام‌های آزمایشی پاک شدن.

قانون‌های گفتگو سمت سرور اعمال می‌شن (نه فقط توی اپ):
- لینک، آیدی (@…) و شماره تماس توی پیام و اسم گروه رد می‌شه (جلوی کلاهبرداری و تبلیغ کانال سیگنال)
- حداکثر یه پیام در هر ۳ ثانیه و ۱۵ پیام در دقیقه برای هر حساب؛ پیام حداکثر ۱۰۰۰ حرف و نمودار حداکثر ۸۰ کندل (۱۲ کیلوبایت)
- هر پیامی که ۳ نفر مختلف گزارشش کنن پنهان می‌شه؛ نویسنده و سازنده‌ی گروه می‌تونن پیام رو حذف کنن
- هر حساب حداکثر ۵ گروه (۳ تا در روز) می‌سازه و توی حداکثر ۳۰ گروه عضو می‌شه
- خوندن گروه‌ها بدون حساب هم ممکنه؛ عضویت و نوشتن حساب سرور لازم داره

**دستیار هوش مصنوعی نصب شده (۲۴ سپتامبر ۲۰۲۶).** جدول و تابع شمارش پیام‌ها
([`20260926000000_tradingo_ai.sql`](../supabase/migrations/20260926000000_tradingo_ai.sql)) نصب شد و اثر انگشت بقیه‌ی پروژه
باز هم یکی موند. Edge Function به اسم `tradingo-coach` ([`supabase/functions/tradingo-coach`](../supabase/functions/tradingo-coach)) هم
کنار توابع اپ دیگه (که بهشون دست نخورد) منتشر شد. تا کلید هوش مصنوعی تنظیم نشه، اپ می‌گه «دستیار هنوز راه‌اندازی نشده».

**دوئل با دوست نصب شده (۲۴ سپتامبر ۲۰۲۶، [`20260927000000_tradingo_duels.sql`](../supabase/migrations/20260927000000_tradingo_duels.sql)).**
اثر انگشت بقیه‌ی پروژه قبل و بعد باز هم دقیقاً یکی بود (۱۹۹۴ شیء). ساختن دوئل، باز کردنش با کد، پنهان بودن امتیاز سازنده تا وقتی
دوست بازی نکرده، ثبت نتیجه، ارسال دوباره، رد شدن نفر سوم، رد شدن امتیاز یا داده‌ی نامعتبر و بسته بودن دسترسی مستقیم به جدول روی سرور
تست شد و حساب‌های آزمایشی پاک شدن.

قانون‌های دوئل سمت سرور:
- هر دوئل یه کد شش‌حرفی داره و فقط یه نفر (غیر از سازنده) می‌تونه بازیش کنه؛ دوئل باز بعد از ۷ روز منقضی می‌شه
- امتیازها باید توی محدوده‌ای باشن که اپ می‌تونه بسازه، و داده‌ی دوئل حداکثر ۲۴ کیلوبایت (۶۵ کندل نمودار، ۸۰ کندل معامله، ۵ سؤال)
- هر حساب حداکثر ۳۰ دوئل در روز می‌سازه؛ دوئل‌های بالای ۹۰ روز پاک می‌شن
- بازی با شمعک کاملاً روی گوشی اجرا می‌شه و به سرور نیازی نداره

**گزارش مشکل درس‌ها نصب شده (۲۴ سپتامبر ۲۰۲۶، [`20260928000000_tradingo_reports.sql`](../supabase/migrations/20260928000000_tradingo_reports.sql)).**
اثر انگشت بقیه‌ی پروژه قبل و بعد دقیقاً یکی بود (۱۹۹۴ شیء) و نسخه‌ی سرور ۴ شد. ثبت گزارش مهمون، رد شدن داده‌ی نامعتبر و بسته بودن
خوندن جدول از API عمومی روی سرور تست شد و گزارش آزمایشی پاک شد. سقف روزانه‌ی هر حساب (۲۰) قبلش روی PostgreSQL محلی تست شده بود.

کاربر با پرچم بالای صفحه‌ی درس، مرحله‌ی جلوی چشمش رو گزارش می‌ده (جواب اشتباه، غلط تایپی، نمودار، متن گنگ یا مشکل دیگه، با توضیح اختیاری).
گزارش‌ها رو توی **SQL Editor** این‌طوری ببین:

```sql
select created_at, lesson_id, step_index, step_type, reason, message
  from public.tradingo_reports where status = 'new' order by created_at desc;
-- بعد از درست کردن: update public.tradingo_reports set status = 'fixed' where id = '…';
```

**حذف حساب از داخل اپ نصب شده (۲۴ سپتامبر ۲۰۲۶، [`20260929000000_tradingo_account_delete.sql`](../supabase/migrations/20260929000000_tradingo_account_delete.sql)).**
نسخه‌ی سرور ۵ شد و اثر انگشت بقیه‌ی پروژه باز هم دست نخورد. کاربر با رمزش تأیید می‌کنه؛ حساب، نشست‌ها، پیشرفت، لیگ، عضویت و پیام‌های گروه‌ها
(با کم شدن تعداد اعضا)، مصرف دستیار و دوئل‌هایی که ساخته پاک می‌شن. توی دوئل‌هایی که حریف بوده نتیجه برای دوستش می‌مونه ولی اسمش
می‌شه «حساب حذف‌شده». روی PostgreSQL محلی با داده‌ی واقعی و روی سرور با یه حساب آزمایشی (که خودش حذف شد) تست شد.

`lesson_id` و `step_index` دقیقاً همون درس و مرحله توی `src/content` هستن (شماره‌ی مرحله از صفر). هر حساب روزی ۲۰ گزارش و همه با هم
(مهمون‌ها هم) روزی ۱۰۰۰ گزارش می‌تونن بفرستن. گزارشی که بدون اینترنت ثبت بشه روی گوشی می‌مونه و بعداً خودش فرستاده می‌شه.

**پنل مدیریت نصب شده (۲۴ سپتامبر ۲۰۲۶، [`20260930000000_tradingo_admin.sql`](../supabase/migrations/20260930000000_tradingo_admin.sql)).**
اثر انگشت بقیه‌ی پروژه قبل و بعد دقیقاً یکی بود (۱۹۹۴ شیء). همه‌ی حالت‌ها اول روی PostgreSQL محلی (نصب از صفر، نصب دوباره و حذف کامل)
و بعد روی سرور با حساب‌های آزمایشی تست شد و داده‌ی آزمایشی پاک شد. Edge Function دستیار هم (نسخه‌ی ۲) منتشر شد تا کلید رو از پنل بخونه.

- **مدیر:** ستون `role` توی `tradingo_accounts`. توی اپ هیچ راهی برای مدیر شدن نیست و کاربرها چیزی ازش نمی‌بینن. ایمیل (یا شماره‌ی) صاحب اپ
  فقط روی سرور توی جدول `tradingo_admin_logins` ثبت می‌شه
  ([`20261002000000_tradingo_email_login.sql`](../supabase/migrations/20261002000000_tradingo_email_login.sql)، نسخه‌ی ۸) و حسابی که با اون
  وارد بشه (یا همگام بشه) خودش مدیر می‌شه. اضافه کردن توی SQL Editor:
  `insert into public.tradingo_admin_logins (login) values ('owner@example.com') on conflict do nothing;`
  چون ایمیل هنوز تأیید نمی‌شه، ایمیلی رو اضافه کن که صاحبش باهاش ثبت‌نام کرده. کد راه‌اندازی نسخه‌ی ۷ با همین نسخه حذف شد.
  بعد از اون، مدیرها از خود پنل بقیه رو مدیر می‌کنن. پنل توی **پروفایل ← پنل مدیریت** (روی گوشی و app.chartoon.net/admin) پیدا می‌شه.
- **نصب نسخه‌ی ۸ (۲۴ سپتامبر ۲۰۲۶):** روی سرور نصب شد و اثر انگشت بقیه‌ی پروژه دست نخورد (۱۹۹۴ شیء). کد راه‌اندازی قبلی پاک شد
  و حساب ایمیلی صاحب اپ ساخته و توی `tradingo_admin_logins` ثبت شد؛ با ورود، مدیر شد و پنل براش باز شد.
- **آیدی و عکس پروفایل (نسخه‌ی ۹، ۲۴ سپتامبر ۲۰۲۶):** روی سرور نصب شد و اثر انگشت بقیه‌ی پروژه دست نخورد. همه‌ی حساب‌ها آیدی
  خودکار (مثل `trader48213`) گرفتن که از تب پروفایل عوض می‌شه؛ پروفایل عمومی (`tradingo_profile`) ایمیل، شماره، معامله‌ها و نقش حساب رو نشون نمی‌ده.
- **ورود با ایمیل (نسخه‌ی ۸):** `tradingo_register` و `tradingo_login` با ایمیل یا شماره کار می‌کنن. `tradingo_sign_up` و `tradingo_sign_in`
  برای نسخه‌های قدیمی اپ (فقط شماره) می‌مونن و همون قانون‌ها رو دارن. هر حساب ایمیل یا شماره داره (یا هر دو).
- **گروه‌ها:** همه‌ی گروه‌ها (رسمی و ساخته‌ی کاربرها) با تعداد عضو، پیام، پیام پنهان و گزارش باز؛ دیدن همه‌ی پیام‌های یه گروه (پنهان‌شده‌ها هم)،
  رفتن به خود گروه، و حذف گروه‌هایی که کاربرها ساختن (گروه‌های رسمی حذف نمی‌شن). گفتگو با دستیار هوش مصنوعی فقط روی گوشی خود کاربره و به سرور نمی‌رسه، پس مدیر هم نمی‌بینه‌ش.
- **گزارش‌ها:** پیام‌هایی که کاربرها گزارش دادن، پرگزارش‌ترها اول؛ «حذف پیام» یا «مشکلی نداره».
- **بستن چت:** یه ساعت، ۲۴ ساعت، ۷ روز یا تا وقتی باز بشه. کاربر پیام‌ها رو می‌خونه ولی نمی‌تونه بفرسته یا گروه بسازه.
- **مسدود کردن:** از همه‌ی دستگاه‌ها خارج می‌شه، دیگه وارد نمی‌شه (بعد از رمز درست، خطای «مسدود» می‌گیره)، پیام‌هاش پنهان می‌شه و از لیگ هفته بیرون می‌ره. برگشت‌پذیره.
- **پاک کردن همه‌ی پیام‌های یه حساب**، و حذف هر پیام از داخل خود گفتگو (نگه داشتن انگشت روی پیام).
- مدیر نمی‌تونه خودش رو مسدود کنه، چتش رو ببنده یا مدیری خودش رو برداره، و مدیر دیگه رو قبل از برداشتن مدیریش نمی‌شه مسدود کرد.
- **سابقه:** هر کار مدیرها با اسم مدیر و حساب هدف توی `tradingo_admin_log` ثبت می‌شه (یک سال نگه داشته می‌شه).
- **کلید هوش مصنوعی:** از تب «هوش مصنوعی» پنل عوض می‌شه (کلید، سرویس، مدل، آدرس API و سقف روزانه) و توی `tradingo_settings` می‌مونه.
  کلید هیچ‌وقت به اپ برنمی‌گرده (پنل فقط چهار حرف آخرش رو نشون می‌ده) و فقط `tradingo_ai_gate` که مخصوص Edge Function (نقش service_role) هست بهش دسترسی داره.
  اگه توی پنل کلیدی نباشه، Secrets داشبورد (پایین) استفاده می‌شن.

### راه‌انداختن دستیار (یه بار)

ساده‌ترین راه: توی اپ برو **پروفایل ← پنل مدیریت ← هوش مصنوعی** و کلید رو بذار. راه جایگزین: توی داشبورد Supabase برو به
**Edge Functions → Secrets** و این‌ها رو اضافه کن (اسم‌ها با `TRADINGO_` شروع می‌شن تا با تنظیمات اپ دیگه قاطی نشن؛ کلیدی که
توی پنل ذخیره بشه به اینا اولویت داره):

| اسم | مقدار |
|---|---|
| `TRADINGO_AI_API_KEY` | کلید سرویس هوش مصنوعی (اگه توی پنل ثبت نشده) |
| `TRADINGO_AI_PROVIDER` | `anthropic` (پیش‌فرض) یا `openai` برای هر سرویس سازگار با OpenAI |
| `TRADINGO_AI_MODEL` | اسم مدل؛ برای Anthropic پیش‌فرض `claude-sonnet-5` |
| `TRADINGO_AI_BASE_URL` | فقط برای حالت `openai`: آدرس API، مثلاً `https://api.example.com/v1` |
| `TRADINGO_AI_DAILY_LIMIT` | سقف پیام هر کاربر در روز (پیش‌فرض ۴۰) |

کلید فقط روی سرور می‌مونه و هیچ‌وقت توی اپ نمی‌ره. قبل از انتخاب سرویس، شرایط استفاده‌ش رو ببین؛ بعضی سرویس‌ها
(از جمله Anthropic) فقط توی کشورهای مشخصی ارائه می‌شن و ممکنه برای کاربرهای بعضی کشورها مجاز نباشن.

قانون‌های دستیار سمت سرور: فقط حساب‌های سرور (با نشست معتبر) می‌تونن بپرسن، هر حساب روزی حداکثر
`TRADINGO_AI_DAILY_LIMIT` پیام داره، و دستیار آموزش می‌ده و سیگنال یا توصیه‌ی پول واقعی نمی‌ده. گفتگو فقط روی دستگاه کاربر
ذخیره می‌شه؛ سرور فقط تعداد پیام‌های روزانه رو نگه می‌داره.

هشدارهای Security Advisor درباره‌ی `tradingo_*` عمدی‌ان:
- «RLS enabled, no policy»: یعنی جدول‌ها از بیرون مستقیم در دسترس نیستن (همون چیزی که می‌خوایم).
- «SECURITY DEFINER function executable by anon»: این توابع تنها راه ورود اپ هستن و هر کدوم رمز یا نشست رو بررسی می‌کنن.
  نقش `authenticated` بهشون دسترسی نداره، چون چارتون از Supabase Auth استفاده نمی‌کنه.

قفل شدن بعد از ۸ رمز اشتباه، ذخیره و بازیابی پیشرفت، لیگ، خروج، جلوگیری از دسترسی مستقیم به جدول‌ها و حذف کامل.

## ۲. کلیدها

فقط **Project URL** و **Publishable key** توی اپ می‌رن (هر دو عمومی‌ان):

```bash
EXPO_PUBLIC_SUPABASE_URL=https://jasgepmskcsyvqoesocc.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

این دو توی فایل `.env.local` هستن (توی Git نمی‌ره). برای بیلدهای EAS همین دو متغیر رو با `npx eas-cli@latest env:create` اضافه کن.

**کلید secret (یا service_role) هیچ‌وقت نباید توی اپ، این مخزن یا جایی که کاربر بهش دسترسی داره بره**؛ همه‌ی RLS رو دور می‌زنه و
به داده‌ی همه‌ی اپ‌های این پروژه دسترسی کامل می‌ده. اگه جایی به اشتراک گذاشته شده، از **Project Settings → API Keys** عوضش کن.

## ۳. رفتار اپ

- تا وقتی SQL اجرا نشده (یا سرور در دسترس نیست)، ثبت‌نام و ورود روی همون دستگاه انجام می‌شه و اپ بی‌خطا کار می‌کنه.
- بعد از نصب، ثبت‌نام‌های جدید روی سرور ساخته می‌شن. کسی که قبلاً فقط روی دستگاه ثبت‌نام کرده، از **پروفایل → حساب کاربری → انتقال به سرور** با رمزش حسابش رو منتقل می‌کنه.
- پیشرفت ۳ ثانیه بعد از هر تغییر روی سرور ذخیره می‌شه و موقع ورود از دستگاه دیگه با پیشرفت اون دستگاه ادغام می‌شه.

## قدم‌های بعدی (مرحله‌ی ۳ نقشه‌ی راه)

- تأیید ایمیل با کد (یه سرویس ارسال ایمیل مثل Resend با دامنه‌ی chartoon.net) و فراموشی رمز
- تأیید شماره با کد پیامکی (OTP) از طریق یه Edge Function و سرویس پیامک ایرانی
- ثبت XP سمت سرور با اعتبارسنجی بیشتر (الان XP هفتگی سقف داره و فقط می‌تونه بالا بره)
- گروه‌بندی واقعی لیگ‌ها (دسته‌های ۳۰ نفره) و صعود و سقوط سمت سرور
- انتقال محتوای درس‌ها به دیتابیس برای اضافه کردن درس بدون آپدیت اپ
