# وصل کردن تریدینگو به Supabase

اپ بدون سرور هم کامل کار می‌کنه و پیشرفت رو روی دستگاه نگه می‌داره. با Supabase این‌ها روشن می‌شن:

- ثبت‌نام و ورود با شماره موبایل و رمز عبور (فعلاً بدون کد تأیید)، روی همه‌ی دستگاه‌ها
- ذخیره‌ی ابری پیشرفت و ادغام خودکار بین دستگاه‌ها (هیچ درسی از دست نمی‌ره؛ عددها بیشترین مقدار رو نگه می‌دارن)
- لیگ هفتگی با بازیکن‌های واقعی (صندلی‌های خالی با رقبای شبیه‌سازی‌شده پر می‌شن)

## پروژه‌ی مشترک: تریدینگو جدا از بقیه‌ی اپ‌ها

پروژه‌ی Supabase تریدینگو با اپ‌های دیگه مشترکه، پس تریدینگو عمداً یه گوشه‌ی جدا داره:

- همه‌ی چیزهایی که می‌سازه اسمش با `tradingo_` شروع می‌شه: چهار جدول (`tradingo_accounts`، `tradingo_sessions`، `tradingo_progress`، `tradingo_weekly_xp`) و چند تابع.
- از **Supabase Auth استفاده نمی‌کنه**؛ حساب‌ها (موبایل + رمزِ هش‌شده با bcrypt) توی `tradingo_accounts` هستن. پس کاربرهای تریدینگو توی `auth.users` و جدول‌هایی مثل `profiles` یا `users` اپ‌های دیگه نمی‌رن و تنظیمات ورود پروژه (مثل Confirm email) لازم نیست تغییر کنه.
- به هیچ جدول، تابع یا تنظیمی از اپ‌های دیگه دست نمی‌زنه. قبل از نوشتن، اسم‌های موجود پروژه بررسی شد و هیچ‌کدوم با `tradingo_` شروع نمی‌شه.
- جدول‌ها RLS دارن و هیچ policy ندارن؛ یعنی از بیرون مستقیم خونده یا نوشته نمی‌شن و اپ فقط از طریق توابع `tradingo_*` باهاشون کار می‌کنه.
- حذف کامل: [`supabase/tradingo_uninstall.sql`](../supabase/tradingo_uninstall.sql) فقط همین‌ها رو پاک می‌کنه.

## وضعیت فعلی

**نصب شده (۲۳ سپتامبر ۲۰۲۶).** بعد از نصب، اثر انگشت ساختار کل پروژه (جدول‌ها، ستون‌ها، policyها، توابع، تریگرها و دسترسی‌ها، به‌جز `tradingo_*`)
قبل و بعد مقایسه شد و دقیقاً یکی بود؛ تعداد کاربرهای `auth.users` و policyها هم تغییری نکرد. ثبت‌نام، ورود، ذخیره، بازیابی، لیگ و خروج
از طریق API عمومی و با کد خود اپ روی سرور تست شد و حساب‌های آزمایشی بعدش پاک شدن.

هشدارهای Security Advisor درباره‌ی `tradingo_*` عمدی‌ان:
- «RLS enabled, no policy»: یعنی جدول‌ها از بیرون مستقیم در دسترس نیستن (همون چیزی که می‌خوایم).
- «SECURITY DEFINER function executable by anon»: این توابع تنها راه ورود اپ هستن و هر کدوم رمز یا نشست رو بررسی می‌کنن.
  نقش `authenticated` بهشون دسترسی نداره، چون تریدینگو از Supabase Auth استفاده نمی‌کنه.

## ۱. نصب (یه بار)

توی داشبورد Supabase برو به **SQL Editor → New query**، کل فایل
[`supabase/migrations/20260924000000_tradingo.sql`](../supabase/migrations/20260924000000_tradingo.sql)
رو بچسبون و **Run** بزن. اجرای دوباره‌ش ضرری نداره.

این فایل قبل از تحویل روی PostgreSQL 16 با نقش‌های مشابه Supabase و PostgREST تست شده: ثبت‌نام، شماره‌ی تکراری،
قفل شدن بعد از ۸ رمز اشتباه، ذخیره و بازیابی پیشرفت، لیگ، خروج، جلوگیری از دسترسی مستقیم به جدول‌ها و حذف کامل.

## ۲. کلیدها

فقط **Project URL** و **Publishable key** توی اپ می‌رن (هر دو عمومی‌ان):

```bash
EXPO_PUBLIC_SUPABASE_URL=https://jasgepmskcsyvqoesocc.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

این دو توی فایل `.env.local` هستن (توی Git نمی‌ره). برای بیلدهای EAS همین دو متغیر رو با `npx eas-cli@latest env:create` اضافه کن.

**کلید secret (یا service_role) هیچ‌وقت نباید توی اپ، این مخزن یا جایی که کاربر بهش دسترسی داره بره**؛ همه‌ی RLS رو دور می‌زنه و
به داده‌ی همه‌ی اپ‌های این پروژه دسترسی کامل می‌ده. اگه جایی به اشتراک گذاشته شده، از **Project Settings → API Keys** عوضش کن.

## ۳. رفتار اپ

- تا وقتی SQL اجرا نشده (یا سرور در دسترس نیست)، ثبت‌نام و ورود روی همون دستگاه انجام می‌شه و اپ بی‌خطا کار می‌کنه.
- بعد از نصب، ثبت‌نام‌های جدید روی سرور ساخته می‌شن. کسی که قبلاً فقط روی دستگاه ثبت‌نام کرده، از **پروفایل → حساب کاربری → انتقال به سرور** با رمزش حسابش رو منتقل می‌کنه.
- پیشرفت ۳ ثانیه بعد از هر تغییر روی سرور ذخیره می‌شه و موقع ورود از دستگاه دیگه با پیشرفت اون دستگاه ادغام می‌شه.

## ۴. کجای کد؟

| فایل | کار |
|---|---|
| `supabase/migrations/20260924000000_tradingo.sql` | جدول‌ها و توابع `tradingo_*` |
| `src/lib/supabase.ts` | ساخت کلاینت (بدون Supabase Auth؛ اگه کلیدها نباشن اپ آفلاین کار می‌کنه) |
| `src/lib/cloud.ts` | تماس با توابع سرور، نشست، همگام‌سازی و لیگ |
| `src/lib/auth.ts` | ثبت‌نام، ورود، خروج و انتقال حساب به سرور |
| `src/app/account.tsx` | صفحه‌ی حساب کاربری |

## قدم‌های بعدی (مرحله‌ی ۳ نقشه‌ی راه)

- تأیید شماره با کد پیامکی (OTP) از طریق یه Edge Function و سرویس پیامک ایرانی
- ثبت XP سمت سرور با اعتبارسنجی بیشتر (الان XP هفتگی سقف داره و فقط می‌تونه بالا بره)
- گروه‌بندی واقعی لیگ‌ها (دسته‌های ۳۰ نفره) و صعود و سقوط سمت سرور
- انتقال محتوای درس‌ها به دیتابیس برای اضافه کردن درس بدون آپدیت اپ
