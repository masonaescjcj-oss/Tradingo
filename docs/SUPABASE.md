# وصل کردن تریدینگو به Supabase

اپ بدون سرور هم کامل کار می‌کنه و پیشرفت رو روی دستگاه نگه می‌داره. وقتی Supabase وصل بشه، این‌ها روشن می‌شن:

- ثبت‌نام و ورود با شماره موبایل و رمز عبور (فعلاً بدون کد تأیید)
- ذخیره‌ی ابری پیشرفت و ادغام خودکار بین دستگاه‌ها (هیچ درسی از دست نمی‌ره؛ عددها بیشترین مقدار رو نگه می‌دارن)
- لیگ هفتگی با بازیکن‌های واقعی (صندلی‌های خالی هنوز با رقبای شبیه‌سازی‌شده پر می‌شن)

## ۱. ساخت جدول‌ها

توی داشبورد Supabase برو به **SQL Editor** و کل فایل
[`supabase/migrations/20260923000000_init.sql`](../supabase/migrations/20260923000000_init.sql)
رو اجرا کن. این فایل سه جدول `profiles`، `progress` و `weekly_xp` رو با Row Level Security می‌سازه:
هر کاربر فقط پیشرفت خودش رو می‌خونه و می‌نویسه و جدول لیگ برای کاربرهای واردشده فقط‌خواندنیه.

اگه Supabase CLI داری: `npx supabase link --project-ref <ref>` و بعد `npx supabase db push`.

## ۲. تنظیم ورود با موبایل (بدون کد)

ثبت‌نام با **شماره موبایل و رمز عبور** انجامه و فعلاً کد پیامکی لازم نیست. برای اینکه به سرویس پیامک نیازی نباشه، اپ برای هر شماره یه ایمیل جایگزین
به شکل `09123456789@mobile.tradingo.app` می‌سازه و با Email/Password سوپابیس کار می‌کنه. پس:

- **Authentication → Providers → Email** روشن باشه.
- **Confirm email** رو **خاموش** کن (وگرنه سوپابیس منتظر تأیید ایمیلی می‌مونه که وجود نداره).
- بعداً که ورود با کد پیامکی (OTP) اضافه بشه، همین حساب‌ها به شماره‌ی واقعی وصل می‌شن.

## ۳. کلیدها

از **Project Settings → API** آدرس پروژه (Project URL) و از **API Keys** کلید Publishable رو بردار و
فایل `.env.example` رو به `.env.local` کپی کن:

```bash
EXPO_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

این دو مقدار عمومی‌ان و توی اپ قرار می‌گیرن؛ امنیت داده‌ها رو RLS تأمین می‌کنه.
**هیچ‌وقت** رمز دیتابیس یا کلید secret / service_role رو توی اپ یا این فایل نذار.

برای بیلدهای EAS همین دو متغیر رو با `npx eas-cli@latest env:create` (یا از داشبورد Expo) به محیط‌های production و preview اضافه کن.
راه سریع‌تر: `npx eas-cli@latest integrations:supabase:connect --link <project-ref>` که متغیرها رو خودش می‌نویسه.

بعد از تغییر `.env.local`، سرور توسعه رو دوباره اجرا کن (`npx expo start`).

## ۴. کجای کد؟

| فایل | کار |
|---|---|
| `src/lib/supabase.ts` | ساخت کلاینت (اگه کلیدها نباشن `null` برمی‌گردونه و اپ آفلاین کار می‌کنه) |
| `src/lib/auth.ts` | ثبت‌نام، ورود و خروج با موبایل و رمز؛ بدون سرور، حساب روی همون دستگاه ذخیره می‌شه |
| `src/lib/cloud.ts` | حساب سوپابیس، ادغام پیشرفت، همگام‌سازی خودکار ۳ ثانیه بعد از هر تغییر، جدول لیگ |
| `src/app/account.tsx` | صفحه‌ی حساب کاربری |
| `src/lib/league.ts` | ترکیب بازیکن‌های واقعی با رقبای شبیه‌سازی‌شده |

## قدم‌های بعدی (مرحله‌ی ۳ نقشه‌ی راه)

- ثبت XP سمت سرور با Edge Function تا تقلب سخت‌تر بشه (الان فقط سقف و «فقط افزایشی» بودن XP هفتگی توی دیتابیس کنترل می‌شه)
- گروه‌بندی واقعی لیگ‌ها (دسته‌های ۳۰ نفره) و صعود و سقوط سمت سرور با `pg_cron`
- تأیید شماره با کد پیامکی (OTP) و ورود با گوگل
- انتقال محتوای درس‌ها به دیتابیس برای اضافه کردن درس بدون آپدیت اپ
